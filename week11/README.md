本周的学习与工程实践聚焦于“全栈开发环境的高级持续集成”与“项目成果的工程化可视化交付”两大核心维度。通过在原生 Linux 环境下深入探索 Docker 镜像的层叠文件系统与持久化机制，成功将物理仿真引擎 pybullet、计算机视觉库 OpenCV 与 ROS2 机器人操作系统进行多维融合与镜像固化；同时，利用 Git 工作流打通了 GitHub Pages 静态网页部署链路，实现了项目全生命周期文档的云端自动化发布。具体内容总结如下：

一、 Docker 进阶架构控制、增量联合文件系统与镜像持久化机制
在分布式机器人项目研发中，确保团队内部开发环境的绝对一致性是提高协作效率的前提。本周我深入研究了 Docker 的进阶指令集与底层的联合文件系统（UnionFS）拓扑架构。

Docker 镜像层叠存储原理：理解了 Docker 镜像是由多个只读层（Read-Only Layers）叠加而成的，而容器启动时会在最上层加载一个可写层（Container Layer）。我们在容器内部安装的所有软件和依赖，本质上都暂存极易丢失的可写层中。

环境持久化的工程痛点解决：为了将配置好的环境固化，我重点实践了镜像的更新与保存机制。通过准确获取容器的短 Hash 编码（Container ID），熟练运用 docker commit 命令，将容器当前的可写层无损地熔断、压缩并转化为一个新的、只读的静态镜像层（Image Layer）。进一步学习了利用 docker save 将镜像导出为 .tar 归档文件，以及 docker load 恢复镜像的完整流。
这种“环境即代码”的持久化控制，彻底斩断了由于系统版本更迭、依赖库升级导致的“环境崩溃”隐患，为团队协同提供了开箱即用的标准底座。

二、 课堂任务一深度解构：ROS2 容器环境高级配置与多源依赖库集成
在环境配置实践中，我以原生 ROS2 容器为母本，针对机器人开发的两大核心支柱——物理运动学仿真与计算机视觉感知，进行了高密度的第三方开源库编译与集成：

物理仿真层集成（pybullet）：在容器内成功部署了轻量级、高效的跨平台物理仿真引擎 pybullet。理解了其作为机器人动力学、碰撞检测以及强化学习（RL）虚拟训练场的核心价值，为后续摆脱实体硬件束缚、在纯净 Linux 终端下开展机械臂运动学逆解验证和四足机器人步态规划仿真做好了算力准备。

视觉感知层集成（OpenCV）：无缝配置了 opencv-python 计算机视觉核心库。这一步打通了图像数字矩阵从硬件采集、色域空间转换（BGR 到灰度/HSV）、空域高斯滤波去噪到边缘特征提取（Sobel/Canny 算子）的完整预处理链路。

多源环境融合成像：通过将 pybullet（控制与物理反馈）和 OpenCV（视觉感知）共同植入 ROS2 的分布式通信网络中，我成功在容器内部构建起了一个“感知-决策-控制-仿真”四位一体的闭环软件开发环境。最终，通过执行 docker commit，我将这一套耗费大量调试心血的高定制化环境封装成了可复用的专用标准开发镜像，实现了研发环境的资产化积累。

三、 课堂任务二深度解构：GitHub Pages 静态网页发布与技术文档成果交付
现代软件工程不仅要求代码具备高鲁棒性，更要求技术成果具备规范的可视化交付能力。本周期末/期中项目深化的核心任务之一，是利用 GitHub Pages 服务将个人的 GitHub 作业仓库及研发文档进行全方位的网页化重构与云端部署。

静态站点部署流与分支控制：我深入学习了基于分布式版本控制系统的网页发布工作流。在远程 GitHub 仓库中激活 GitHub Pages 引擎，精细化设置网页发布的托管源分支（如 main 或专用的 gh-pages 分支）。理解了静态网页服务器如何自动捕获分支根目录下的 index.html 或经过渲染的 Markdown 文档，并在全球内容分发网络（CDN）上进行高速映射。

Jekyll 静态站点生成器语义化配置：在进阶实践中，我初步涉猎了基于 Ruby 的 Jekyll 主题配置架构。理解了如何通过修改 _config.yml 配置文件，一键引入高可读性、符合现代前端审美和移动端响应式布局的技术主题。将原本散落在仓库各个角落的、枯燥的 Markdown 实验报告和代码说明，自动编译并渲染为带有级联目录、代码高亮、图表内嵌的现代化静态技术博客站点。
这极大提升了个人代码仓库的成果展示度与开源规范性，实现了研发成果的高质量优雅交付。
